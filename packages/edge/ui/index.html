Why Busto

An AI that pays your invoices is a liability —
unless it can't be tricked.

Hand an agent your accounts payable and you inherit its failure modes: a hidden instruction buried in a PDF, a vendor that doesn't exist, a swapped wallet address, the same invoice paid twice — and every figure and document shipped off to someone else's cloud. Busto is built so none of that can move money. It reads each invoice on your own hardware, takes the truth from your books rather than the document, and routes every payment through six independent gates. The model can propose. It can never pay.

The six gates

A payment is impossible unless it clears every one. No single component — least of all the model — can move funds.

  • G0

    Input decode

    Obfuscated text — base64, homoglyphs, zero-width characters, Morse, nesting — is normalized and decoded before the model ever sees it. A hidden "pay this now" is flagged, logged, and rejected, never executed.

  • G1

    Role bounding

    The model only reads and proposes. It has no authority to settle — moving money is not a tool it can call.

  • G2

    Deterministic truth

    Vendor, purchase order, and the payee wallet are read from your ERP, not the document. The numbers that matter never come from the page being verified.

  • G3

    Recipient re-check

    Immediately before signing, plain code re-checks the recipient against the wallet on file. A swapped address stops here, on the machine that holds the keys.

  • G4

    Human approval

    A deliberate hold-to-authorize in the Edge role. Nothing moves without a person, and signing authority lives only in the key-holding role — never in the code that runs the model.

  • G5

    On-chain safety

    Pinned chain and token, a checksummed address, an exact-amount transfer with no blanket approvals, and confirmations before it's called settled.

    Not a mock

    Real inference, on-device

    QVAC runs the OCR, the multimodal read, the ERP retrieval, and the explainer locally. No cloud AI, ever — confidential financials never leave the building.

    A real on-chain transfer

    Settlement is an actual test USD₮ transfer on Ethereum Sepolia, with a real transaction hash you can open in a block explorer. No simulated success states.

    Two node roles, separable by design

    Inference and key custody are split into distinct roles: the Orchestrator reads and verifies, the Edge holds the wallet and signs. The delegated link between them is real and logged, and is proven with both roles on one host — running them on separate machines is the pending step. What you are running here is the consolidated single-Mac build.

    Disclosed by design

    Every remote call is listed in the open remote_apis.json — only non-AI endpoints: the chain RPC and a blind, end-to-end-encrypted P2P relay.
